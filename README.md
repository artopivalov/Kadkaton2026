# Kadkaton: прототип с тремя билдами

Королевская битва реализована: боковой портал **Battle Royale** в игровом лобби запускает матч, когда все игроки стоят внутри. Для одиночного теста добавлены два неподвижных бота. Участники получают случайную Legendary палочку и руну, HP ×10, отталкивание и притяжение ×3. Лава заполняет арену за минуту; умершие наблюдают, последний живой побеждает, одновременная смерть — ничья. Камера каждого участника фиксируется к центру при старте. [Спецификация режима](docs/battle-royale.md).


## Реализованные правки лобби и UI от 8 октября 2026

Требования реализованы в прототипе. Полное описание — разделы 5 и 14 `GameDesignDocument.md`.

- Максимально простой туториал на полу лобби: четыре меловых рисунка с подписями **HOLD**, **RELEASE**, **MOVE**, **SWITCH** — удержание для зарядки, отпускание для выстрела, движение джойстиком и переключение навыков существующим переключателем Safe / Normal / Special.
- Убрать экранные подсказки сверху и снизу. Вверху оставить только кнопку меню, убрать верхние health bar и mana bar.
- Над персонажем расположить полоску здоровья, под ней — полоску маны. Существующий индикатор зарядки палочки вокруг персонажа оставить: это зарядка, не загрузка.
- Информацию о рунах временно скрыть; механики рун сохраняются.
- Исправлен баг по наблюдению пользователя: камера лобби неподвижно стоит по центру и отвязалась от персонажа. Восстановлено следование за локальным персонажем по обеим осям. Свободная камера отладки генерации описана отдельно.

Проверены 149 существующих тестов и два новых теста рендера; собраны все три билда. Вид лобби и следование камеры проверены в браузере без ошибок консоли. Реальный телефон и сетевой сеанс отдельно не проверены.

## Единая страница запуска

На macOS откройте `StartKadkaton.command` двойным кликом в Finder: команды вводить не нужно. Файл при первом запуске ставит зависимости (`npm install`), запускает `npm run launch` и открывает страницу запуска `launcher.html`. Повторный двойной клик, пока всё работает, просто открывает эту страницу. Чтобы остановить сервер, закройте окно терминала или нажмите Ctrl+C.

`npm run launch` собирает все три билда, запускает сервер соединения вместе с публичным туннелем Cloudflare (если установлен `cloudflared`) и открывает `launcher.html`: дебаг, игра, просмотр сцен и панель сервера. Кнопка «Игра» ведёт на адрес игрового сервера (порт 8701): только с него работают Host game и Join game, потому что там же находится матчмейкинг. Публичная ссылка для игроков из других сетей печатается в терминале и показана в панели сервера.

## Публикация с вшитым адресом сервера

Чтобы любой игрок, открывший игру, находил именно ваш сервер, адрес вшивается в билд. Для этого у Mac нужен **постоянный** публичный адрес с HTTPS (страница на Netlify работает по HTTPS и не может обращаться к незащищённому серверу). Временный адрес Cloudflare меняется при каждом запуске, поэтому используется ngrok со статическим доменом.

Один раз:
1. `brew install --cask ngrok` (уже установлен на этом Mac).
2. Создайте бесплатный аккаунт на ngrok.com, скопируйте Authtoken (Your Authtoken) и выполните в Терминале `ngrok config add-authtoken ВАШ_ТОКЕН`.
3. В панели ngrok откройте Universe → Domains и создайте бесплатный статический домен вида `имя.ngrok-free.app`.
4. Скопируйте `kadkaton.config.example.json` в `kadkaton.config.json` и впишите в `serverUrl` адрес `https://имя.ngrok-free.app`.
5. `npm run package`: соберёт `dist/game` с вшитым адресом и архив `dist/Kadkaton-game.zip`. Без `kadkaton.config.json` (или переменной `KADKATON_SERVER_URL`) билд ищет сервер, с которого открыт.
6. Загрузите папку `dist/game` на Netlify (app.netlify.com/drop) и отправьте игрокам ссылку на сайт. Открывать игру двойным кликом по `index.html` нельзя: браузеры блокируют модули с файла, игре нужен веб-адрес.

Перед каждой игрой: `StartKadkaton.command`. Если в конфиге домен ngrok, он сам запустит ngrok с этим доменом (флажок «Public tunnel» в панели) и сообщит в логе, что адрес совпадает с вшитым. Tailscale Funnel (`*.ts.net`) тоже поддерживается, если у вас обычный аккаунт Tailscale. Mac, терминал и интернет должны работать, пока идёт игра.

## Запуск и сборка

Из папки проекта: `python3 -m http.server 8000`.

- Исходники (по умолчанию отладочная площадка): http://localhost:8000/
- Отладочный билд: http://localhost:8000/dist/debug/
- Отладка генерации: http://localhost:8000/dist/generation/
- Основной билд: http://localhost:8000/dist/game/

Собрать все три: `npm run build` или `node scripts/build.mjs`. Только один: `npm run build:debug` / `npm run build:game` / `npm run build:generation`. Тесты: `npm test` или `node --test`. Для сборки и тестов нужен Node.js; внешних зависимостей и шага установки нет.

Для телефона открыть тот же путь через `http://<IP компьютера>:8000` в одной локальной сети. Для передачи основного билда достаточно папки `dist/game`; она работает как самостоятельный статический сайт. Отладочная сцена и её тестовые данные туда не копируются. Сборка заменяет только помеченные ею выходные папки; отказывается перезаписывать чужую папку без маркера. `dist/` исключена из Git.

## Сцены

Меню одинаковое для трёх билдов: превью с мгновенным перекрашиванием, имя и цвет с сохранением в localStorage, Play, заглушки Host game / Join game.

**Отладочная площадка:** 17 подписанных постаментов: Fireball, Ice, Lightning, Air, Earth, Nature, Gravity, Light, Crystal, Blood, Storm, Void, Mirror, Orbit, Comet, Prism, Test Wand. Подойдите к постаменту — палочка автоматически заменится даже в занятом слоте. Постамент остаётся на месте. Повторная замена происходит при новом подходе; простое стояние рядом не сбрасывает заряд. Три подвижные тренировочные мишени и постоянная стенка позволяют проверять урон, отталкивание и рикошеты. Стартовая палочка — Test Wand.

**Основной билд:** лобби с безопасной Test Wand и тремя доступными порталами: Forest, Cave, Library. Переход происходит, когда все игроки стоят в одном портале. Локации содержат соответственно 10/15/20 круглых POI, соединённых коридорами; лес линейный, пещера с короткими ответвлениями, библиотека с цепочками тупиков до трёх POI. Камера следует за игроком по обеим осям. В каждой локации доступны ближние и дальние враги своего биома, финальный босс и общий лут. Победа требует уничтожить всех врагов последней комнаты, включая босса; затем доступен возврат в лобби. После смерти можно вернуться в лобби и начать заново.

В обеих сценах можно выбросить палочку нажатием на слот и подобрать её в пустой слот. Обычный предмет на земле не заменяет занятую палочку. После выбрасывания действует задержка повторного подбора 0,8 с. Правило автоматической замены на постаменте существует только там, где сцена содержит постаменты.

**Отладка генерации:** отдельная сборка `generation`, свободная камера без коллизий (джойстик / WASD / стрелки). Выберите Forest, Cave или Library и seed, затем нажмите Regenerate. Повтор того же seed воспроизводит карту. Используются те же генератор и полный спавн врагов/предметов, что в основной игре. Камера не ограничивает спавн. Персонаж не отображается, симуляция боёв заморожена для осмотра. Обе отладочные сцены исключены из основной сборки.

## Управление и баланс

Игра портретная: на широком экране 9:16, на вертикальном телефоне — вся доступная высота и ширина. В локациях камера следует за персонажем. Справа — непрерывный вертикальный слайдер зума: снизу отдаление (.35), сверху приближение (1.25), начальное значение .72; масштаб меняется плавно. Слева внизу — вертикальный ползунок Safe/Normal/Special снизу вверх, на игровом поле — плавающий джойстик под пальцем, справа — слот палочки и слот руны. Ползунок переключается свайпом, нажатием или стрелками при фокусе; Home/End выбирают края.

Зарядка идёт от удержания джойстика или игрового поля, даже в центре джойстика, без движения. WASD/стрелки — движение и удержание для зарядки; противоположные клавиши останавливают движение, сохраняя зарядку. Все атаки срабатывают при отпускании. Safe не стреляет. Смена режима, выбрасывание, смена палочки на постаменте, отмена жеста и потеря фокуса отменяют заряд.

Временные числа собраны в `src/balance.js`. Минимум дальности Normal — 1% максимума, минимум урона — 0,01%; рост идёт по квадрату заряда. Fireball растёт от радиуса 0,6 до 12. Серия из 20 нажатий по 40 мс наносит менее 5% урона одного полного Fireball. Значения и кривая ещё требуют балансировки. Стена Earth существует 6 секунд — временное число из файла баланса.

Временное правило коллизий: стены блокируют персонажа, отталкиваемые цели, обычные снаряды, линию Lightning и волну Ice. Камень Earth рикошетит, удар Lightning с неба применяется напрямую за стеной. GDD ещё не определяет все взаимодействия атак со стенами; эти правила нужно проверить отдельно. Здоровье, мана, руны, враги, локации и боссы реализованы с временными числами. Самоурон исключён, friendly fire составляет 50%. Реальный сетевой транспорт ещё не реализован: Host / Join остаются заглушками, сетевой план находится в разделе 16 GDD.

## Структура и проверка

- `scripts/build.mjs`: изолированные статические сборки.
- `src/scene.js`: точка входа сцены, заменяемая сборкой.
- `src/scenes/debug.js` / `lobby.js`: отдельные сцены и их данные; `createScene(profile?, {seed})`.
- `src/balance.js` / `wands.js`: параметры и определения всех палочек, правило friendly fire (`PVP_BALANCE`).
- `src/simulation.js`: общее состояние, заклинания, коллизии, предметы, постаменты и порталы.
- `src/rng.js`: детерминированный генератор по seed.
- `src/main.js` / `renderer.js` / `style.css`: ввод, заменяемая графика и адаптивный UI.

## Подготовка к мультиплееру

Сети пока нет, но симуляция уже рассчитана на нескольких игроков (подробности и принятые решения: раздел 16 GDD).

- Состояние мира — обычные JSON-данные: `state.players` (у каждого игрока `id`), предметы, снаряды, эффекты, стены, `seed`.
- Правила принимают id игрока: `release(state, id)`, `setMode(state, id, mode)`, `dropWand(state, id)`. Новые игроки добавляются через `addPlayer(state, profile)`, уходят через `removePlayer`.
- Один тик: `step(state, inputs, dt)`, где `inputs[id] = {x, y, held, commands}`. Команды `setMode`, `drop`, `release`, `cancel` выполняются в начале тика, поэтому отпускание между кадрами не теряется. `main.js` собирает ввод локального игрока и вызывает `step` с фиксированным шагом 1/60 с.
- Friendly fire наносит 50% урона (`PVP_BALANCE.friendlyFireMultiplier`); атака не поражает своего владельца. Здоровье уменьшается от фактического урона; `hits` и `damage` сохраняются для отладки.
- Портал открывается группе, только когда в нём стоят все игроки: `readyPortal(state)`. Локальный цикл выполняет переход всей группы в выбранную локацию.
- Карту должен строить каждый клиент по общему seed: `createRandom(seed)` для чистых генераторов, `nextRandom(state)` внутри симуляции. Генератор карты реализован в `src/generator.js`.
- Не сделано: транспорт, хост и снимки состояния, кнопки Host/Join, столкновения игроков.

## Сетевая игра

Для игры из разных сетей: `npm run server` (нужен Node.js; один раз `npm install` для пакета `ws`). Откроется HTML-панель `http://localhost:8700/`: Start / Stop, флажок публичного туннеля Cloudflare (нужен `cloudflared`), адреса сервера, список комнат и консоль логов. Закрытие вкладки панели останавливает сервер. Сервер собирает и раздаёт `dist/game` на порту 8701 и принимает матчмейкинг по `/ws`.

Игроки открывают игру с адреса сервера (локального, из сети или публичного): **Host game** создаёт комнату, **Join game** показывает список комнат. Игровой трафик идёт напрямую между игроками (WebRTC); сервер нужен только для знакомства. Если открыть игру не с адреса сервера или сервер не запущен, меню сообщит, что сервер недоступен. Вкладка хоста должна оставаться активной.

Код: `server/` (панель, комнаты, раздача игры), `src/net/` (`host.js`, `client.js`, `snapshot.js`, `codec.js`, `matchmaking.js`, `rtc.js`, `loopback.js` для тестов). Подробности и ограничения: разделы 16.4–16.7 GDD. Запасного пути без прямого соединения пока нет.

## Временные правила нового прототипа

- Обычные POI независимо выбираются с вероятностями 50% бой / 50% загадка; финальная арена босса боевая. Доступны десять новых комнат и последовательность из 5–7 случайно расставленных плит, с общим прогрессом для соло и группы.
- После завершения POI подойдите к сундуку. Он открывается один раз и создаёт ровно два общих предмета; каждый независимо имеет шанс 50% быть боевой палочкой или руной. Подбор идёт в порядке игроков в симуляции. Занятый слот не заменяется. В начале локации каждый игрок сразу получает случайную боевую палочку; входная площадка безопасна.
- Руны: от одного до пяти случайных модификаторов по редкости Common–Legendary; доступны Damage, Range, Size, Projectile Speed, Charge Time, Spread, Mana Cost. Величины непрерывные от −20% до +50/60/70/80/90% по редкости по полезности, штрафы выпадают с шансом 20%; повторы перемножаются. Модификаторы пересчитывают Normal и Special. Слот руны позволяет выбрасывать предмет.
- Враги: skeleton / archer, goblin / goblinArcher, orc / orcArcher. Ближние преследуют и атакуют рядом; дальние выпускают прямые снаряды, стены блокируют их. В коридорах 1–2 врага, в боевых POI 3–6; характеристики растут с прогрессом и размером группы. Спавн полный и детерминированный, агро 450; после атаки враг и ближайшая группа сохраняют атакующего целью.
- Боссы имеют временные паттерны: радиальные пули, конус, удар по зафиксированной области. Красное предупреждение появляется за 1.8 с; атака соответствует его положению и форме. Cave/Library boss — временные названия и способности.
- Игрок: 100 здоровья, 100 маны, восстановление 3 маны/с, базовый Normal стоит 6 маны, Special 32 до модификаторов. При смерти игрок перестаёт двигаться/стрелять; Return to lobby сбрасывает текущий проход. Эти значения, коэффициенты врагов, загадка и правила результата — решения прототипа, а не утверждённый финальный дизайн.
- Карта и состояние сериализуются в JSON, генерация зависит от seed. Сохраняются отдельные игроки, групповой портал, shared loot и friendly fire как основа будущего кооператива; WebRTC, комнаты, сервер и предсказание клиентов остаются следующим этапом.

Новые модули: `src/generator.js` — граф и геометрия карты; `src/locations.js` — вход в локацию, спавн, ИИ, POI и сундуки; `src/scenes/generation.js` — свободная камера. Проверки генерации и прохождения: `tests/locations.test.js`.

## Обновление после игрового теста

Внесены все 11 правок GDD. Арены и коридоры просторнее, радиус агро после повторного теста установлен в 450, развилки имеют два выхода ±45°. Победа наступает после уничтожения всех врагов последней комнаты, включая босса. Fireball получает splash-взрыв, Ice Special гарантированно удаляется после завершения. На момент этих правок UI включал плавающий джойстик, читаемый индикатор здоровья и полосы над волшебниками (новое целевое размещение ресурсов описано выше); слоты устойчиво принимают нажатия для выбрасывания.

Добавлены Nature, Gravity, Light и Crystal, общая модель семи базовых статов и редкости предметов с цветными обводками. Отладочная площадка расширена: все 17 палочек на постаментах, переключатель Item rarity и станция случайных рун. Для новой руны подойдите к станции; она заменяет текущую. Выйдите из радиуса и вернитесь для повторной выдачи. В описываемой версии бонусы руны показаны под статусом заклинания; по новым требованиям выше эта информация теперь временно скрыта.

`src/items.js` отвечает за генерацию предметов и модификаторы; `src/wands.js` — базовые характеристики и производные параметры. Числа и временные правила находятся в `src/balance.js`, подробности — в приложении GDD. Дополнительно проверены новые заклинания, JSON-детерминизм, редкости, дробная дальность Ice и условие победы. Реальный телефон пока не проверен.


## Новое расширение и повторный тест

Добавлены Blood, Storm, Void, Mirror, Orbit, Comet, Prism и все 11 особых эффектов рун. Crystal начинается с Uncommon; Blood/Mirror — Rare, Storm/Orbit — Epic, Void/Comet/Prism — Legendary. Каждый источник соблюдает минимальную редкость. Палочки получают сохраняемые случайные статы −20%…+30%; Rare+ руны имеют шанс 30% получить один особый эффект.

Новые враги: Прыгун, Крючник, Чародей; редкие биомные — Грибной пастух, Кристальный панцирь, Переписчик. Пастух призывает убиваемые грибы. ИИ и паттерны находятся в `src/enemies.js`, расширенные заклинания — в `src/spells.js`.

Внесены все десять правок повторного теста: групповое постоянное агро, заметный расход маны, увеличенные арены/коридоры, урон контролирующих атак, ослабление пробивания, новые диапазоны рун и случайные статы, прозрачные предупреждения. Числа находятся в `src/balance.js`.

На площадке доступны выбор особого эффекта руны, спавн любого врага и очистка. После смерти нажмите Reset playground. Все новые комнаты-загадки и 5–7 плит реализованы.


## Комнаты-загадки

Forest: огоньки и сад корней; Cave: каменный бильярд и созвездие; Library: световой коридор, возвращающийся ключ, кристаллическая развилка и живая библиотека. Циферблат, весы и последовательные плиты доступны во всех биомах. Кооператив добавляет объекты/пары или удлиняет последовательность; каждый вариант можно решить одному игроку.

Нужные палочки лежат у входа. Оставьте прежнюю палочку, возьмите нужную и заберите прежнюю после решения. Подсказка комнаты нарисована на её полу, кнопка Reset puzzle появляется в середине экрана; есть и площадка Reset. Ошибки и сброс не удаляют предметы. Боевые заклинания и механизмы загадок не причиняют игрокам урон. После решения механизмы выключаются, препятствия исчезают, общий сундук выдаёт два предмета один раз.

`src/puzzles.js` содержит комнаты и правила; `PUZZLE_BALANCE` и `PUZZLE_POOLS` в `src/balance.js` — временный баланс и пулы. Дополнительные проверки в `tests/puzzles.test.js` покрывают реальные заклинания, доступные маршруты, ошибки, весы без палочки, кооператив, сохранение предметов и сетевые снимки.

## Отклик движения и боя

Джойстик подтягивает центр при выходе пальца за радиус, облегчая разворот. Отрисовка соло/хоста интерполирует позиции между фиксированными тиками. Волшебник слегка покачивается при движении; корпус плавно поворачивается, а игровое направление меняется сразу. Заряд светится на кончике палочки, полная зарядка даёт короткий сигнал готовности. Успешное применение вызывает визуальную отдачу, направленные искры и короткий звук стихии; снаряды оставляют компактный след. Попадания дают всплеск, реакцию цели и числа урона/лечения; несколько попаданий в цель за кадр объединяются. Смертельное попадание сохраняет эффект после удаления врага.

Отклик собственного применения использует предсказание клиента и не повторяется при подтверждении хоста. События попадания передаются хостом отдельно, с ограниченным сроком хранения. Декоративные эффекты не останавливают симуляцию и не расходуют её RNG. `Sound on/off` сохраняет выбор; системный reduced motion отключает покачивание, отдачу и тряску. Реальный телефон и субъективная настройка звучания ещё требуют игрового теста.

### Материалы стихий и усиленная отдача

Все 17 палочек используют отдельные палитры и звуковые материалы. Огонь и Comet оставляют угольки; Ice/Crystal — вращающиеся осколки; Mirror — зеркальные грани; Nature — листья; Blood — капли; Air — воздушные штрихи; Lightning/Storm — разряды; Gravity/Void — частицы, направленные внутрь; Light/Orbit/Test — звёздочки; Prism — разноцветные грани. Частицы появляются при зарядке, выстреле, попадании и вдоль полёта. Длительные поля получили вращающиеся дуги, листья, электрические штрихи и блики; лучи — дополнительные световые слои.

Звуки состоят из короткого тона, низкого тела и фильтрованной текстуры материала; стекло и электричество получают серию коротких щелчков, огонь — треск. Normal имеет до 12 единиц визуальной отдачи, Special до 19; отдача сохраняет направление выстрела при развороте и затухает с обратным качком. Одновременно допускается до 160 частиц и 28 звуковых голосов; предупреждения атак рисуются поверх декоративных эффектов.

Во время зарядки локального игрока появляется полупрозрачный прицел: удлинённое пунктирное направление (300 единиц мира), небольшая стрелка и простой кружок радиусом 6 впереди. Он следует игровому направлению сразу и исчезает при отпускании/отмене, в Safe и после смерти. Обычный маркер показывает направление, а не гарантированное попадание или дальность; Lightning Special сохраняет точную точку удара, зависящую от заряда.

### Плавное отбрасывание и входящий урон

Боевое отбрасывание теперь проходит за 0,24 с с быстрым началом и затуханием; суммарная дистанция и множители Air, рун и Battle Royale сохраняются. Каждый шаг проверяет стены, заблокированная компонента толчка прекращается. Игрок продолжает управлять движением и зарядкой. Импульс хранится в JSON состояния и участвует в сетевом предсказании; при входе в новую сцену сбрасывается. Передвижение механизмов загадок сохраняет свои правила. Настройки находятся в `KNOCKBACK_BALANCE`.

Входящий урон локального игрока получает отдельный низкий удар, короткую виньетку по краям экрана, реакцию персонажа и светлый след потерянного здоровья на полосе. Лечение и безопасное нулевое попадание не дают этого сигнала. Звуковые голоса резервируются для входящего урона, чтобы частые чужие выстрелы его не заглушали. У стихий усилены ударные текстуры, низкое тело, светлое ядро снаряда и двойные затухающие кольца попадания.

## Оформление лобби

Каменный зал по концепту: рунические порталы с вращающимся свечением, фонари, знамёна, зелень и четыре меловые пиктограммы HOLD / RELEASE / MOVE / SWITCH на полу. Рисунки заменяют длинные учебные надписи; здоровье, мана и зарядка остаются у персонажа. Графика — `src/art/lobby.js`, все сборки включают модуль.

### Фоновая музыка

Оригинальная 48-секундная петля при 80 BPM: мягкие колокольчики, щипковый арпеджиатор, тёплая гармония и приглушённый бас. `src/music.js` синтезирует и кэширует стереобуфер; музыка воспроизводится отдельной тихой шиной и не занимает голоса звуков боя. Начинается в игровой сцене после пользовательского жеста, плавно выключается в меню и скрытой вкладке. Sound on/off управляет музыкой вместе с эффектами.
