# Как делать «максимальный сатисфай» в мобильных веб-играх

Инструкция для Claude. Собрана из игр в `D:\AIProjects`: Dice Clash / Dice Battle / Dice Draw
(`dice-clash`), Tilt Drop (`tilt-drop`), Sort Deck 3D (`sort-deck-3d`), CubeMagnet (`cube-magnet`),
Cube Breaker / ArrowMerge (`cube-breaker`), Тетрис-версии (`mono-stuck-tetris`), Harvest
(`firefly-light/Main.html`). Все числа ниже
взяты из рабочего кода этих игр, пользователь их видел и одобрил. Начинай с них, а подгоняй
уже по ощущению.

Когда пользователь пишет «максимально сатисфайно», «сочно», «приятно», он имеет в виду всё,
что описано ниже, сразу и без напоминаний. Коротко: **на каждое действие игрока игра отвечает
сразу по нескольким каналам (движение, свет, частицы, звук, вибрация), ничего не появляется и
не исчезает мгновенно, а каждый успех звучит на ноту выше предыдущего.**

---

## 1. Десять законов

1. **Ядро важнее всего.** Самое главное — как объект слушается пальца: катится, наклоняется,
   прыгает. Если это ощущается деревянно, никакие частицы не спасут. Ядро делаешь и
   полируешь первым.
2. **Никакой мгновенности.** Всё, что появляется, выпрыгивает пружинкой (easeOutBack/elastic).
   Всё, что исчезает, схлопывается облачком. Всё, что перемещается, летит по дуге. В оригинале
   Sort Deck предметы телепортировались, и 3D-версия стала сатисфайной в первую очередь потому,
   что там всё «летает, прыгает и звенит».
3. **Многоканальный отклик.** Любое событие — это пакет: сплющивание, частицы, кольцо-волна,
   вспышка, тряска, звук, вибрация, иногда стоп-кадр и цифра. Одиночное моргание не считается.
4. **Сила по важности.** У эффектов есть лестница: каждый ход < подбор < собранная группа <
   собрано всё < переход уровня. Большое событие обязано ощущаться больше маленького (см. §4).
5. **Звучит материал, нота — сверху и с потолком.** Каждое событие звучит так, как звучало
   бы физически: треск, шмяк, хруст, «ток», хлопок. Сила и комбо наращивают **плотность**
   слоёв и вес, а не высоту. Тональная нота ступени добавляется только на абстрактных
   успехах (матч, подбор) и не выходит за 1400 Гц — фолд на октаву вниз (§8).
6. **Мягкость.** Звуки тёплые, круглые, без визга. Ошибка — мягкое «бум», а не сирена. Пружины
   затухают быстро, без дребезга.
7. **Предвосхищение.** Игра заранее показывает, что сейчас случится: подсвечивает цель, тянет
   объект магнитом, рисует призрак посадки, заранее краснеет от ошибки.
8. **Каскады вместо залпов.** Группа объектов реагирует волной с шагом 30–90 мс, а не разом:
   так событие читается как движение, а не как моргание.
9. **Щедрая хореография награды.** Большая награда — это последовательность маленьких
   событий, растянутая на 0.5–1.5 с: кольцо и аккорд, потом прыжок волной и конфетти, потом
   плавная смена на следующее.
10. **Ошибка не наказывает телом.** Красная виньетка, тряска, дрожь, но без отбрасывания игрока
    и без потери сделанного. Анимацию проигрыша дай досмотреть и только потом показывай карточку.

## 2. Формат проекта (как привык пользователь)

- Один `index.html` без сборки. 3D — three.js **r128** с cdnjs
  (`https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js`), 2D — чистый `<canvas>`
  без библиотек. Рядом `README.md`.
- Картинок и аудиофайлов нет: геометрия, текстуры (canvas) и звук (WebAudio) генерируются в коде.
- Игра живёт в контейнере `#phone`. Уже 768px он на весь вьюпорт, шире — «телефон» 410×820
  по центру (скругление 46px) и переключатель «На весь экран / Смартфон» слева внизу.
  Размер меряется по `#phone` через `ResizeObserver`. **Низкое окно — рамку не сплющивать,
  а уменьшать целиком** (§15): `max-height` на рамке запрещён.
- В консоли есть отладочный объект (`DC`, `TD`, `SD`, `MC`, `CB`): `.test()` запускает автопилот
  и проверяет инварианты, `.run(sec)` синхронно прокручивает игру (в скрытой вкладке
  `requestAnimationFrame` не тикает), `.go(n)` открывает уровень. Флаг `testing` глушит звук,
  вибрацию и тяжёлые эффекты.
- В README есть раздел «Сочность» / «Приятности»: коротко, что происходит при каждом событии.
- Каждое изменение проверяй в превью с мобильным размером 375×812 и смотри ошибки в консоли.
- Пользователь пишет коротко по-русски. Решения, которые он принял, не откатывай (§14).

## 3. Ядро: ощущение управления

### Кубик, который катится за пальцем (Dice Clash — «главное в игре»)
- Пока тянешь, кубик **приподнимается на ребре** пропорционально пути пальца:
  `angle = along / swipeLen * 90°`, где `swipeLen = clamp(cellPx * 1.25, 56, 130)`.
  Сглаживание — `ang += (want - ang) * (1 - exp(-30 dt))`.
- **Точка опрокидывания 45°**: дотянул — тихий «тик», и кубик дальше переваливается сам.
  Отпустил раньше — он падает назад под своим весом (`angV -= 40 dt`) и глухо стукает, громкость
  стука зависит от скорости удара.
- Время переката зависит от того, сколько осталось: `dur = ROLL_DUR * (0.05 + 0.14 * rest^0.8)`.
  Кривая `p = 0.3u + 0.7u²` даёт ускорение к посадке, как при падении.
- Посадка: кубик по пружине чуть переваливается дальше и возвращается, сплющивается, из-под
  рёбер вылетает пыль, по клеткам бежит волна, звучит «ток» и нота маримбы.
- Короткий быстрый свайп (<280 мс и >16 px) или флик (>0.3 px/мс) докатывает кубик, даже если
  он не дошёл до 45°.
- **Буфер ввода**: свайп, сделанный во время переката, запоминается и выполняется сразу после
  посадки. Ни одно действие игрока не должно теряться.
- **Удержание**: держишь палец — кубик катится дальше клетка за клеткой (первый повтор через
  0.19 с, дальше каждые 0.05 с). Повёл палец в сторону больше чем на 26 px — кубик сворачивает.
- Впереди стена: кубик лишь чуть приподнимается (`BLOCK_TILT` с насыщением
  `1 - exp(-raw/0.35)`), а при отпускании стукает. Даже запрет получает свою анимацию.
- Направление свайпа ищется как ближайшая проекция экранных направлений клеток (`cam.sdir`),
  поэтому управление работает при любом повороте камеры.

### Наклон доски (Tilt Drop)
- **Плавающий джойстик**: центр ставится там, где коснулся палец. Если увести палец дальше
  радиуса R = 17% экрана, центр подтягивается следом, поэтому разворот срабатывает мгновенно.
  Отпустил — доска плавно выравнивается.
- Физика — фиксированные подшаги (`while (acc >= SUB && n < 40)`), ускорение катящегося шара
  `× 5/7`, сопротивление качению `exp(-ROLL_DRAG·dt)`.
- Камера слегка смещается от наклона (параллакс), и доска «живёт».
- Гироскоп — по кнопке; положение в момент включения считается «ровным».

### Тап (Sort Deck 3D)
- В ответ на тап сразу что-то движется: коробка выдвигается к игроку (easeOutBack за 0.18 с,
  +0.8 по z, +6% масштаба), сплющивается, звучит «тук» и шорох вытягивания, вибрация 8 мс.
- Под мышью нижняя коробка приподнимается на 0.07 (сглаживание `dt * 14`).

### Общие правила ядра
- Отклик в тот же кадр, без ожидания конца анимации.
- Всё сглаживание не зависит от частоты кадров: `x += (target - x) * (1 - exp(-k dt))`.
- Масштаб подбирай так, чтобы объекты были **крупными**: вид сверху на всё поле в изометрии
  пользователь отверг («мелко»), одобрен крупный план, где камера следит за кубиком.

## 5. Движение

### Пружины вместо твинов для реакций
```
v += (-k * (x - rest) - c * v) * dt;  x += v * dt;     // толчок = добавить к v
```
| Что | k | c | Толчок |
|---|---|---|---|
| Покачивание кубика на ребре после посадки | 950 | 30 | `rockV = 2.3` (упёрся — 3.4) |
| Сплющивание | 700 | 20 | `sqV = −2.4 / −3.4 / −4.2` |
| Клетки поля (волна) | 320 | 16 | `v += −сила·(1 − d/радиус)` с задержкой `d·0.05` с |
| Доска целиком (толчок от «плюх») | 140 | 13 | `bumpV −= 0.5` |

### Сплющивание с сохранением объёма
`scale = (1/√s, s, 1/√s)`. Масштабируй родителя, у которого начало координат на полу, иначе
объект уйдёт в пол. Короткий «чпок» без состояния делается затухающей косинусоидой:
`a = A·e^(−9t)·cos(30t)`, `scale = (1 + 0.55a, 1 − a, 1 + 0.55a)`, A ≈ 0.1–0.24, длительность 0.6 с.
Для падающих предметов бери A пропорционально силе удара: `min(0.16, скорость·0.014)`.

### Появление и исчезновение
- Появление: `easeOutBack(p, 2.2)` или `elastic(p)` за 0.35–0.55 с, с шагом 0.03–0.09 с между
  объектами и тихим «поп» на каждый.
- Исчезновение: раздуться на +30% за первые 30% времени, затем сжаться в ноль
  (`sk < 0.3 ? 1 + sk : 1.3·(1 − (sk − 0.3)/0.7)`), в конце облачко искр.
- Пустая коробка: `scale *= 1 − v²` и лёгкий поворот назад (`rotation.x = −0.9v`) за 0.26 с.
- Крышка «скрытой» коробки откидывается и улетает (k² по времени, 0.38 с), содержимое
  выскакивает пружинкой по очереди.

### Полёт предмета (Sort Deck)
- Квадратичная кривая Безье. Контрольная точка — середина пути, поднятая на `0.8 + 0.2·dist` и
  выдвинутая к камере на 1.6. Время `FLY = 0.46` с, шаг между предметами `STAG = 0.075` с,
  сглаживание easeInOutQuad.
- В полёте масштаб `× (1 + 0.28·sin(πe))` (предмет «приближается»), полный оборот по Y, лёгкий
  наклон `0.3·sin(πe)`. За предметом хвост искр своего цвета (60% кадров).
- Приземлился: сплющивание, кольцо, искры, нота. Предмет встаёт на место своего «призрака».
- Звук взлёта у каждого следующего предмета чуть выше (`430 + k·45` Гц).

### Каскады
- Лопанье группы (CubeMagnet) идёт волной от точки касания по глубине BFS: шаг 0.05 с, перед
  взрывом кубик 0.22 с раздувается, у каждого своя нота вверх по пентатонике.
- Вспышка совпадения в тетрисе: каждая клетка, вставшая в цель, схлопывает кольцо внутрь
  блока (0.32 с), каскадом снизу вверх и слева направо с шагом 0.045 с.
- Волна по клеткам (`tileKick`): задержка растёт с расстоянием, сила падает к краю радиуса.
- **Волна от центра поля** (Harvest): когда решён весь этап, задержка берётся не от точки
  касания, а от расстояния до центра поля — `waveDelay(i) = 0.045 · dist(i, центр)`. Реквизит
  этапа (мешки, поливалки) схлопывается в ноль волной наружу, и из тех же клеток волной
  вырастает реквизит следующего. Волна от центра читается как «поле ожило целиком», волна от
  угла — как «что-то посыпалось».
- **Решённое гаснет плавно, а не кадром.** Разметка, которая была нужна только для решения
  (контуры делянок, цифры), после схождения этапа растворяется той же волной за 0.5 с.
  Пока она исчезала мгновенно, выигрыш читался как сбой отрисовки.

## 6. Стоп-кадр, время и тряска

- Держи игровое время `now` отдельно от реального. `hitstop(sec)` ставит `freeze`, и пока он
  идёт, `dt = 0`: мир замирает на 45–80 мс, а ввод, звук и вибрация уже сработали. Так
  появляется ощущение веса.
- Вся хореография идёт по **игровому** времени через свою очередь событий `after(sec, fn)` /
  `schedule(t, fn)`, а не через `setTimeout`, иначе она не уважает стоп-кадр, паузу и
  ускорение для тестов (`timeScale`).
- Тряска камеры накапливается (`shake += x`) и затухает как `shake *= exp(−11·dt)`; смещение
  случайное по x/y и 0.6 по z. Для «удара» масштабом есть `camKick` (Sort Deck: +1 за заказ,
  максимум 2).
- В важные моменты камера на миг отъезжает на общий план (открылся люк, заставка уровня,
  конец игры) и возвращается к игроку.

## 7. Частицы

Все частицы живут в заранее созданных пулах с кольцевым указателем (700 искр, 320 конфетти,
18 колец). В кадре ничего не создаётся.

- **Искры** — один `THREE.Points` со своим шейдером (размер и прозрачность у каждой свои),
  текстура — мягкая восьмилучевая звёздочка на радиальном градиенте. Жизнь 0.45–0.85 с,
  сопротивление `exp(−2.6·dt)`, гравитация −5. Размер: 40% → 100% за первые 12% жизни, потом
  тает до 45%. Прозрачность: вспышка за 8% жизни, затем `(1 − k)^1.4`. Цвет смешивай
  с белым к центру. Палитра всплеска — `[цвет события, '#FFFFFF', золото '#FFC93C']`.
- **Конфетти** — `InstancedMesh` из бумажек 0.1×0.17 с двусторонним материалом. Гравитация 8,
  предельная скорость падения −2.3 (порхает), покачивание вбок `sin(life·5 + фаза)·0.5`,
  случайное вращение по трём осям, жизнь 1.8–3 с, появление за 0.06 с, исчезновение за 0.35 с.
  Победа — салют из двух точек по 80 штук.
- **Кольцо-волна** — два плоских кольца: цветное и белое с задержкой 0.08 с. Масштаб
  `r·(1 + easeOutCubic(p)·2.6)`, прозрачность `0.85·(1 − p)²`, длительность 0.4–0.65 с.
- **Пыль** из-под рёбер при посадке летит по направлению движения.
- **Ореолы и свечение** — плоскости с мягкой радиальной текстурой и `AdditiveBlending` под
  объектами. Вспышки `emissive` затухают как `exp(−3.2·dt)`.
- В воздухе медленно плавают пылинки: сцена не выглядит мёртвой даже в покое.

## 8. Звук: сухо, чисто, коротко (WebAudio, всё синтезом)

Эталон, к которому надо идти, — **Match Factory**: звуки читаемые, светлые и приятные,
но очень короткие и почти без хвостов. Каждое действие даёт отчётливый отклик, и он
сразу заканчивается. Ничего не гудит, ничего не звенит после.

Две ошибки, каждая из которых уже была и каждая слышна сразу:

- **Писк.** Питч вверх без потолка: каждый следующий успех на ступень выше, ноты уезжают
  за 2 кГц, и получается резь в ушах. Лечится фолдом на октаву вниз (ниже).
- **Орган.** Медленная атака (20–60 мс) + долгий спад (1–2 с) + большая реверберация
  (2.5–3.5 с, wet 0.4) = собор и гудёж. Это была попытка сделать «ASMR-шёпот», и она
  провалилась: звуки сливаются в один тянущийся аккорд, событие перестаёт читаться.
  Отдельно отвергнуто: коричневый шум через lowpass 150–800 Гц как *тело* звука — всё
  становится глухой ватой, и удар, и посадка, и успех звучат одинаково.

Правильный компромисс: **светло, но с потолком; коротко, но с транзиентом.**

### Материал, а не интерфейс

Главный вопрос на каждое событие: **как это звучало бы физически?** Попадание, подбор,
лопание, множитель — это звук самого предмета: треск скорлупы, шмяк помидора, хруст,
«ток» дерева, звон стекла, шкварчание, бульк. Интерфейсных «дзинь» с питчем вверх на
игровые события не ставим — именно от них появляется ощущение дешёвой мобилки.

- Каждому материалу — **свой узнаваемый звук**. Яйцо, помидор и стекло должны отличаться
  на слух с закрытыми глазами, иначе игра звучит однообразно.
- **Тональная нота — сверху и необязательна.** Если событие физическое (разбил, раздавил,
  лопнул), хватает материала. Нота ступени (§ «Мелодия») добавляется там, где событие
  абстрактное: подбор, матч, заполненная ячейка.
- **Сила и комбо — через плотность, а не через высоту.** Важнее событие — больше слоёв
  (щёлк + шмяк + тело), ниже и длиннее тело, громче, чуть больше посыла в ревер.
  Высота при этом не растёт (`matHit` в заготовках).
- Живость — разброс высоты ±4–7 % (`jit()`), а не лестница нот вверх.
- **Одинаковые предметы звучат одинаково.** Лестница нот у повторяющегося действия одного типа
  (поставил поливалку, поставил ещё одну) превращает расстановку в мелодию, которой никто не
  просил, и к пятой штуке начинает пищать. Высоту там не трогаем вовсе, живость даёт `jit()`
  ±4 %, а разницу между событиями — материал: вода, зерно, солома, дерево (Harvest).
- **Откат — это щелчок, а не музыка.** Отмена действия и списание ресурса должны звучать сухим
  «током» дерева: тональная нота на отмене читается как награда.

### Частотный бюджет

| Что | Полоса | Примечание |
|---|---|---|
| Основной тон мелодии | **520–1400 Гц** (C5…) | потолок `F_MAX = 1400`; выше — фолд на октаву вниз |
| Обертон | `2f`, если `2f ≤ 2200` | ×0.2–0.25, длительность ≈ 0.3 от основной |
| Подоктава («тело») | `f/2` | ×0.25–0.4 — вес без гула |
| Стук, посадка | 260–450 Гц | плюс обертон ×1.5 коротко: это и даёт «пластик/дерево» |
| Транзиент (щелчок) | шум 1500–3000 Гц, 20–30 мс | **обязателен**: без него звук мягкий и неточный |
| Треск, хруст, стекло | рой щелчков `bandpass` 1.4–5.6 кГц, Q 3.5, по 10–22 мс | единственное место, где разрешено выше 3 кГц: это **шум**, а не нота, и тихо (≤ 0.15) |
| Шум как воздух | развёртка вниз, 1800 → 420 Гц | не как тело, а как шлейф поверх тона |
| Мастер-срез | highshelf −5 дБ от 3200 + lowpass 5200 Гц (Q 0.4) | снимает резь, не глуша |

Отладочная ловушка в `tone()`: `if (f > 2200) console.warn('SND: слишком высокая частота', f)`.
Предупреждение в консоли — баг, а не вкусовщина. На `noise()` ловушка не нужна: короткий
шумовой щелчок на 5 кГц — это текстура, которая и делает треск настоящим.

### Цепочка

`master (0.6) → highshelf от 3200 Гц, −5 дБ → lowpass 5200 Гц, Q 0.4 →
компрессор (порог −16, ratio 3, attack 4 мс, release 0.2) → выход.`

Компрессор быстрый — он подчёркивает транзиент, а не прижимает его.

Реверберация — **крошечная комната, а не зал**: импульс `(rand·2 − 1)·(1 − i/n)^3.2`,
длина **0.45 с**, lowpass 3000 Гц внутри посыла, **wet 0.12**. Посыл дают только
мелодические ноты (`ding`), и то 0.2–0.3. Стуки, хлопки, треск и шум идут всухую. Длинный
хвост здесь не «половина ощущения», а главный враг: он и есть тот самый орган.

Громкости: главный тон ≤ 0.12, нота аккорда ≤ 0.09, щелчок ≤ 0.07, рой щелчков ≤ 0.15,
мастер 0.6.

### Правила

- Только `sine`. `triangle` допустим лишь ниже 200 Гц; `square` и `sawtooth` запрещены.
- **Атака 4–6 мс**, спад 0.07–0.45 с через `exponentialRampToValueAtTime` от 0.0001.
  Длиннее 0.5 с — только победа и проигрыш.
- Развёртка тона — вниз (`f → f·0.28…0.72` за время звука). Восходящих «вжухов» нет;
  единственное исключение — шумовой «вжух» полёта/выстрела (`bandpass` 260 → 2400 Гц,
  тихо, ≤ 0.08): это воздух, а не нота.
- Шум — **чуть розовее белого**: `v = (v + 0.08·(rand·2 − 1)) / 1.08`, нормировать ×3.2.
  Для тела и воздуха — через `lowpass` с развёрткой вниз; для треска и хруста — через
  `bandpass` с высоким Q. Коричневый шум (коэффициент 0.02) не брать — он мутный.
- Разброс для живости: `playbackRate` шума 0.9–1.1, старт чтения буфера со случайного
  места, высота тона ±4 %.
- Частые звуки — не чаще раза в 40 мс на тип (`gate('crack', 40)`), громкость от силы
  события. Для мягких «шлёп» и «шорох» порог больше: 60–80 мс.
- Каждый звук = **транзиент + тон + тело**. Убери любой из трёх — звук перестаёт читаться.

### Конструктор материала

Любой материальный звук собирается из этих слоёв: берёшь 2–4 подходящих и складываешь.
Числа проверены в прототипе Smash Fest.

| Слой | Как | Для чего |
|---|---|---|
| Щёлк (рой) | 4–9 коротких `bandpass` 1.4–5.6 кГц, Q 3.5, шаг 9–13 мс | треск скорлупы, хруст, стекло |
| Шмяк | `lowpass` 1100–1500 → 200–250 Гц за 0.18–0.24 с | мокрое, мягкое, сочное |
| Чвак | `bandpass` 600–850 Гц, Q 1.5, 0.08–0.1 с | «мякоть» внутри |
| Тело | `sine` 70–115 → 40–55 Гц за 0.1–0.22 с | вес, «гуп» |
| Ток | `lowpass` 1000 Гц 35 мс + `sine` 140 → 90 Гц 50 мс | дерево, мелкий стук |
| Шкварчание | рой 25–75 мс `bandpass` 2.6–5 кГц, очень тихо (0.01–0.04) | жар, газ, пена |
| Вжух | `bandpass` 260–380 → 1300–2400 Гц | полёт, выстрел, взлёт |
| Хлопок | `lowpass` 3000 → 700 Гц 30 мс + `sine f0 → f0·0.28` + выдох | пузырь, губы, капсула |

Готовые сборки — в заготовках кода: `egg`, `tomato`, `crunch`, `glass`, `chunk`, `soft`,
`squirt`, `sizzle`.

### Мелодия успеха: вверх, но с потолком

- **Мажорная** пентатоника от **C5 (523.25 Гц)**, полутоны `[0, 2, 4, 7, 9]` — «конфетная»
  лестница. Минорная от C3 звучит печально и в аркаде не работает.
- Фолд на октаву вниз у потолка: `function fclamp(f){ while (f > 1400) f /= 2; return f; }`
  Тональность сохраняется, полоса не покидается никогда.
- Ступень: `note(step, combo) = 523.25 · 2^((PENTA[s % 5] + 12·⌊s/5⌋) / 12)`, где
  `s = step + min(combo, 4)`. Комбо добавляет ступени, а не октавы.
- Аккорд — **короткое арпеджио вверх** `[0, +4, +7]` с шагом 0.07 с, не одновременный
  аккорд: так слышно движение.
- Победа — четыре ноты пентатоники с шагом 0.11 с, пятая выше и длиннее, и щепоть шума
  1600 → 500 Гц поверх. Проигрыш — `[0, −3, −7]` вниз с шагом 0.15 с плюс низкий тон.
- **Где мелодия обязательна:** экран результата — звёзды (по ноте на звезду), победа,
  проигрыш. Там она и работает лучше всего, потому что событие одно и ему никто не мешает.
- Обертон `×2` у `ding` — самая пискливая часть звука. Он уже ограничен условием
  `2f ≤ 2200`, но если слышно звон, первым делом убирай именно его.

### Инструменты

Семь примитивов закрывают всю игру; всё остальное — их комбинации.

- `blip(f)` — тап по объекту: шум 2600 → 900 Гц (20 мс) + `sine f → f·0.45` за 90 мс
  (атака 4 мс) + `f/2 × 0.3`.
- `tock(f)` — стук дерева/пластика: шум 1800 → 600 Гц (25 мс) + `f → f·0.72` за 0.1 с +
  короткий обертон `f·1.52 × 0.3` на 55 мс. Основа посадок, ударов, закрытий.
- `ding(f)` — маримба: `f` 0.34 с с посылом в ревер 0.3 + `2f × 0.22` коротко (если
  `2f ≤ 2200`) + `f/2 × 0.25`. Единственный инструмент с хвостом — только для мелодии.
- `clicks(n, vol, f0, f1, gap)` — рой коротких `bandpass`-щелчков: основа треска,
  хруста и стекла. Четыре щелчка — скорлупа, семь — хруст, девять — стекло.
- `swish()` — воздух на полёте: шум 1800 → 420 Гц, 0.16 с, ×0.035.
- `thud()` — удар кучи: шум 1200 → 300 Гц (40 мс) + `sine 180 → 70 Гц`.
- **`pop(vol, f0)` — хлопок губами / лопнувший пузырь.** Самый вкусный примитив, его
  обычно и не хватает: шум 3000 → 700 Гц (30 мс) + `sine f0 → f0·0.28` за 70 мс
  (атака 4 мс) + `f0/2 × 0.4` на 0.1 с + «выдох» шумом 700 → 260 Гц через 40 мс.
  `f0` 620–880 Гц: ниже перестаёт читаться как хлопок и превращается в «бум». Разным
  событиям — разный `f0` (в Toy Drop 3D капсула лопается на 880 − 60·k, посадка в деку —
  на 620 − 30·i). Резонансный фильтр с высоким Q не нужен: «пузырь» делает падение тона.
- `tap()` — мягкое нажатие: шум 1500 → 500 Гц + `sine 300 → 150`. Ставить на любой
  `pointerdown` вместо щелчка.
- `rustle()` — лёгкий воздух 1400 → 420 Гц ×0.03, подмешивать к посадкам и закрытиям.
- Ошибка: шум 700 → 220 Гц + `sine 220 → 90` + вторая нота 165 → 110 Гц со сдвигом 70 мс.

`AudioContext` создавай и возобновляй (`resume()`) на первом `pointerdown`. Кнопка звука
сохраняется в `localStorage`, при `testing` звук выключен целиком.

### Когда можно отступить

Тёмная тихая палитра (длинные хвосты, низкие ноты) уместна только в медленных
созерцательных играх, где событий мало и между ними есть тишина. Как только событий
больше одного в секунду — она превращается в кашу. По умолчанию делай сухо.

### Как проверять

1. В консоли нет предупреждений ловушки (ни одной **ноты** выше 2200 Гц).
2. Быстро натапай десяток событий подряд: они должны оставаться раздельными. Если слышен
   непрерывный гул — хвосты длинные, режь реверберацию и спад.
3. Пройди уровень до конца: если к концу звук стал тоньше и звонче — лестница сломана,
   нужен фолд.
4. Закрой глаза и вслепую определи, что произошло: разные материалы и разные события
   должны отличаться на слух, а не только громкостью.
5. Слушай на динамике телефона: он задирает верх.

## 10. Предвосхищение: показать до того, как случится

- **Магнит к своей цели** (Tilt Drop): в радиусе `2.6·r` лунки шарик своего размера мягко
  тянет к центру (`сила 11·k`, гашение `exp(−5k·dt)`), а ободок лунки подсвечивается заранее.
  Чужой шарик не проваливается, а выскакивает пружинкой.
- **Реакция цели на наклон** (Dice Clash): наклоняешь кубик к грани — если ход верный, грань
  тянется к кубику, как к магниту, и вокруг неё зелёное кольцо. Если неверный — грань дрожит и
  краснеет, а сторона кубика, которой ударишься, мигает красным.
- **Подсветка клетки** (Dice Draw): при наклоне клетка, которую покрасит сторона, мягко светится.
- **Призраки** (Sort Deck): в подносе заказа стоят полупрозрачные товары, покачиваясь
  (`sin(now·1.4 + k·1.3)·0.45`). Прилетевший товар встаёт на место призрака, призрак схлопывается
  за 0.12 с.
- **Призрак посадки** (CubeMagnet, тетрис): пунктирный контур места, куда встанет объект; красный,
  если там будет проигрыш. Посадку обводи контуром, а не заливкой — иначе призрак не отличить от
  поставленной фигуры.
- **Доступное пульсирует**: нижние коробки обведены пульсирующей рамкой.
- **Опасность заранее**: когда дека заполнена на `cap − 1`, ячейки и счётчик пульсируют
  красным и один раз звучит мягкий сигнал. Круг в CubeMagnet меняет цвет: зелёный → жёлтый →
  красный и мигает.

## 11. Прогресс, праздник, переходы

- **Хореография награды** (заказ в Sort Deck, 0.66 с): t=0 — кольцо, аккорд, вибрация, толчок
  камеры; t=0.3 — товары подпрыгивают волной (шаг 0.05 с), раздуваются и лопаются в искры и
  конфетти своего цвета; t=0.44 — поднос делает оборот, появляется следующий заказ, его призраки
  выпрыгивают по очереди.
- **Праздник победы** (Tilt Drop): волна подсветки по всем уложенным шарикам в порядке укладки
  (шаг `min(0.08, 0.9/n)`), на каждом искры и вспышка, на последнем аккорд. Потом доска уезжает
  вниз (easeIn 0.55 с), новая падает сверху с easeOutBack и лёгким наклоном (0.8 с), фон
  перетекает в новую палитру. Надпись — случайная из «Красота! / Идеально! / Супер!».
- **Новый уровень** (Dice Clash): экран уходит в темноту и выходит на новом этаже, клетки
  поднимаются волной (easeOutBack 0.5 с с задержками), сверху падает собранный кубик. Удар —
  стоп-кадр и ударная волна, детали кубика разлетаются по дугам с 1–2 оборотами, и каждая
  шлёпается на свою клетку со своей нотой.
- **Сборка уровня** (Sort Deck): коробки падают под гравитацией 34 с отскоком 0.2 и
  сплющиванием от силы удара, задержка по колонке 0.07 с, по ряду 0.03 с. Подносы выпрыгивают
  elastic-ом с шагом 0.09 с.
- **Цифры**, а не слова: `+100`, `3 / 6`, `×2`, `−1 ♥`. Всплывают с перелётом масштаба
  (0.3 → 1.25 → 1, вверх и растворяются). Счёт «подпрыгивает» (`scale 1.18` за 0.28 с,
  перезапуск CSS-анимации через `void el.offsetWidth`).
- **Трата ресурса должна быть видна** (Harvest): списание рисуется там, где произошло действие,
  а не только в шкале. Крупное `−1` всплывает в центре поля (масштаб 0.3 → 1.25 → 1), 0.35 с
  висит, потом по дуге улетает в шкалу энергии, и шкала «подпрыгивает» ровно на прилёте. Пока
  число просто менялось в шапке, пользователь списания не замечал вовсе.
- **Платить только за откат.** Энергию (жизни, ходы) снимать за отмену сделанного, а не за сами
  действия: когда игра берёт плату за правильный ход, играть страшно. Правильное действие
  бесплатно, цена — у кнопки «назад».
- **Комбо**: быстрые успехи подряд (окно 1.4–3 с) повышают ноты и множитель очков.
- **Прогрессия для удовольствия**: новые механики вводятся по одной, а между ними идут
  «уровни для удовольствия» с большим количеством «плюх». Начало маленькое и плотное:
  большие пустые первые уровни пользователь забраковал.

### Переход между этапами внутри уровня (Harvest)

Уровень из нескольких этапов на одном поле — это те же переходы, что между уровнями, только
поле остаётся. Порядок, который сработал: этап сошёлся → пауза 0.3–0.5 с, чтобы игрок увидел
собственное решение → реквизит этапа схлопывается в ноль волной от центра → из тех же клеток
волной вырастает реквизит следующего → и только потом возвращается управление.

- **Чистить следы предыдущего этапа.** Частицы воды, оставшиеся от поливалок на выросшей
  пшенице, выглядят как мусор: на входе в новый этап гасим пулы (`clearParticles()`).
- **Баннер этапа — только название**, без номера уровня и без «N уровней открыто», и начиная
  со второго уровня: на первом он перекрывает обучение.

### Обучение: учить в момент, когда правило понадобилось

- **Отдельный тутор-уровень без помех.** Первый уровень — маленькое поле, никаких препятствий,
  по одному объекту на механику. Он существует, чтобы показать жесты, а не чтобы его решать.
- **Жест показывает рука, а не текст.** На канвасе рисуется палец (`Path2D`, кончик
  указательного — опорная точка) и проигрывает сам жест: ведёт рамку от угла к углу для
  выделения, тапает с нажимом, свайпает в сторону хода. Рука рисуется **поверх** всего, иначе
  уходит под текстуру поля.
- **Пульсирующий палец не исчезает.** Там, где ждут тапа, палец остаётся на месте и пульсирует
  (нажим `0.5 + 0.5·sin(now·5)`), а цель обводится мигающей рамкой. Пропадающая анимация
  читается как «я опоздал посмотреть».
- **Карточка — белая, лаконичная, над полем.** Две строки: что сделать и чем это стоит.
  Никаких заголовков «ШАГ 1 · ПОСЕВ» — пользователь их забраковал. Карточка снимается сразу
  после сделанного действия и сама через 11 с.
- **Правило показывается в тот момент, когда впервые понадобилось, а не по сценарию.**
  Самая ценная находка. В Harvest игрок может перекрыть себе дорогу собственными тюками;
  правило «тюк можно разобрать за энергию» показывается **первый раз, когда он сам себя
  запер**: этап не откатывается, выезжает карточка, соседний тюк пульсирует рамкой с рукой.
  Второй раз уже обычный откат — объяснять дважды незачем.
- **Подсказка не зовёт к недоступному действию.** Показывать её только если игрок правда
  может это сделать прямо сейчас (рядом есть тюк и хватает энергии), иначе она издевательство.
- **Урок разовый и помнится между сессиями** (`localStorage`), иначе он становится назойливым
  уже к третьему уровню.
- **Отвергнуто: сценарный тутор с нарочным тупиком.** Вести игрока по заранее собранному
  маршруту, который заведомо упирается в тупик, чтобы «показать правило», — выглядит как
  подстава. Учить надо на собственной ошибке игрока, а не на подстроенной.

## 12. Ошибка и проигрыш — мягко

- Ошибка: стоп-кадр 80 мс, тряска, красная виньетка по краям
  (`radial-gradient(ellipse at center, transparent 40%, rgba(255,30,80,.55) 100%)`, гаснет за 0.6 с),
  объект дрожит, сердечко лопается. Игрока **не отбрасывать** и сделанное не отнимать:
  пользователь попросил, чтобы кубик оставался на клетке («элемент стратегии»).
- Запрет без штрафа (стена, занятая сторона без жизней): короткий стук и дрожь, больше ничего.
- Проигрыш: сначала досмотреть анимацию (шарик улетает — 1.2 с, дека трясётся — 0.9 с), потом
  карточка. Кнопка «Ещё раз» / «Переиграть этаж N» возвращает ту же раскладку.
- Где можно, делай без тупиков: уложенные шарики утоплены вровень и по ним можно катиться, а
  если игрок загнал себя в тупик, детали сами перепрыгивают на новые места.

## 13. Красивая картинка (three.js r128)

- `renderer.outputEncoding = sRGBEncoding`, `toneMapping = ACESFilmicToneMapping`,
  экспозиция около 0.74, `setPixelRatio(min(dpr, 2))`, `antialias: true`.
- Все цвета переводи в линейное пространство: `new THREE.Color(hex).convertSRGBToLinear()`.
- **Отражения без HDR-файлов**: маленькая сцена «студии» (сфера с градиентом на canvas и 2–3
  светлые панели) → `PMREMGenerator.fromScene(...)` → `scene.environment`. Глянец появляется
  сразу на всём.
- Свет: `HemisphereLight` (тёплый верх, землистый низ, 0.3) + солнце с мягкими тенями
  (`PCFSoftShadowMap`, `radius 5`, карта 1024 на телефоне и 2048 на ПК, `normalBias 0.02`) +
  холодный заполняющий свет 0.3. Стена или подложка за сценой ловит мягкие тени.
- Никаких острых углов: скруглённые бруски (`ExtrudeGeometry` из скруглённого контура с фаской)
  и шарики в углах. Глянцевые материалы (`roughness 0.34–0.45`).
- Фон — градиент со светлым пятном в центре, палитра насыщенная, но мягкая. Картинка на
  стартовом экране — inline SVG в стиле игры, медленно парит.
- **Цвета, по которым игрок матчит, должны читаться мгновенно** (ArrowMerge, одобрено):
  насыщенные тёплые оттенки с максимально разнесённым тоном —
  `#C80F18 #7B3AC9 #F7C515 #3DAA3F #0FA3B8 #1F5FD6 #D6246E #EA5A04` (EggMerge: оранжевый последним — только когда уровню нужны все 8 цветов, на ранних путался с жёлтым и красным; красный тёмный #C80F18). Отражения слабые
  (`envMapIntensity` 0.45, у затенённых 0.18), `roughness` 0.44, экспозиция 0.84, свет
  тёплый (солнце `#FFE6C8`, небо `#FFF1DE`). Пастель + сильные отражения + ACES выбеливают
  цвета, и их не различить.
- Всё процедурно: текстуры рисуются на canvas (дерево, рамки, звёздочки, мягкие пятна).

**Для плоской 2D-игры на canvas** (Harvest) работают те же правила, плюс свои:

- **Тень важнее формы предмета.** Серия правок по камням ушла почти вся в тень: тень не по
  форме контура — и камень «воткнут углом в землю», а не лежит. Если тень не ложится по форме
  (объект нарисован почти сверху, а тень — сбоку), её честнее убрать совсем: без тени предмет
  читается как лежащий, с неправильной — как сломанный.
- **Перспектива мелких предметов на поле.** Предмет, нарисованный сильно сбоку, невозможно
  отцентрировать в клетке: он «висит». Рисуй почти сверху и опорное основание делай
  **эллипсом**, а не кругом — круг сразу выбивается из перспективы.
- **Ряд запаса ставь на подложку-деку**, в той же перспективе, с ячейками под каждый предмет.
  Предметы, стоящие прямо на фоне («в траве»), выглядят потерянными; дека собирает их в один
  объект интерфейса. Саму фишку при этом не трогай — пользователь просил деку, а не новые
  фишки, и перерисовку фишек забраковал дважды.
- **Картинка на карточке итога — это добыча, а не абстракция.** Цветок, оставшийся от прошлой
  игры, заменён стожком тюков теми же градиентом и перетяжками, что у тюков на поле: карточка
  должна показывать то, что игрок только что собрал.
- **Фишка под рамкой выделения увеличивается и пульсирует** (`×1.12 + 0.055·sin(now·9)`) —
  бесплатный способ показать «эта область принадлежит вот этому мешку».

## 14. Что пользователь отверг (не повторять)

- **Слова во всплывающих надписях.** «Оставь только цифры, а все слова удали»: никаких
  «Слой собран!», «Тупик!», «ТОЧНО!». Большой баннер «Уровень N» можно оставить.
- **Правила и подсказки на стартовом экране.** Остаются логотип, название, «Играть» и рекорд.
  Постоянную подсказку внизу во время игры тоже убрали.
- **Прозрачность** («прозрачность фигня, ещё хуже»). Объекты непрозрачные.
- **Мелкий общий план.** Нужен крупный план со слежением.
- **Резкие звуки** (меандр, пила, шипящий шум).
- **«Дзинь» вместо звука материала.** Тональные UI-ноты с питчем вверх на попадания,
  множители и комбо: от них игра звучит дешёвой мобилкой. Событие должно звучать своим
  материалом, а сила — плотностью слоёв (§8).
- **Высокие частоты и питч вверх.** Ноты, уехавшие за 2 кГц, восходящие «вжухи», «тики» на
  2 кГц: «звуки слишком высокочастотные, это надо прям сильно починить». Полоса и потолок — §8.
- **«ASMR-шёпот»: медленная атака, длинные хвосты, большая реверберация.** «Какого-то органа
  навалил, что там за эхо». Попытка исправить это коричневым шумом и низкими нотами дала
  обратную крайность — глухую вату, где все события звучат одинаково. Нужный ориентир —
  Match Factory: сухо, чисто, коротко (§8).
- **Большие пустые первые уровни.**
- **Отбрасывание игрока после ошибки.**
- **Мгновенные появления и телепорты.**
- **Ярко-бледная пастель на глянце** («кубики сложно считать, где какой цвет»): для цветов,
  которые надо различать, только насыщенная тёплая палитра (§13).
- **Тень не по форме предмета.** «Такое впечатление, что камень углом воткнули в землю».
  Либо тень повторяет контур и направление света, либо её нет совсем (§13).
- **Сценарный тутор, который подстраивает игроку ошибку.** Правило показывают в момент, когда
  игрок сам в него упёрся (§11).
- **Заголовки в окнах подсказок** («ШАГ 1 · ПОСЕВ») и номер уровня в баннере этапа.
- **Перерисовка фишки, когда просили окружение.** Просьбу «сделай подставку под поливайки»
  нельзя исполнять перерисовкой самих поливаек: «сами поливайки не трогай».

Если пользователь сам просит то, что противоречит этим принципам (например, проигрыш в
«спокойной» игре), делай как он просит: его слово важнее этого документа.

## 15. Техника, без которой сочность ломается

- **Рамка-«телефон» на низком окне уменьшается целиком, а не сплющивается.** Это правило
  уровня «делать сразу во всех проектах»: дизайн игры рассчитан на `410×820` плюс отступ
  `1rem`, то есть ему нужно 852 px высоты окна, а у ноутбучного браузера высота вьюпорта
  обычно 700–900. Привычный `max-height: calc(100dvh − 2rem)` на рамке — **ловушка**: ширина
  остаётся 410, режется только высота, пропорции телефона ломаются, шапка съедает долю поля,
  а всё, что считается «от оставшейся высоты» (у нас поднос), садится на свой минимум — в
  Sudoku Blast фишки в ленте схлопывались с `.69` до `.46`, ровно отменяя сделанную накануне
  работу. Игрок это чинит зумом браузера на 80%, и это верный признак, что раскладка не та.
  Правильно — отдать рамке её честные `410×820` и уменьшать её целиком:
  ```js
  function fitFrame(){                       // зовём из layout(), layout висит на 'resize'
    if (phone.classList.contains('wide') || innerWidth < 768){ frameScale = 1; phone.style.transform = ''; return; }
    var fit = Math.min(1, (innerHeight - 32) / 820, (innerWidth - 32) / 410);
    frameScale = clamp(fit, .4, 1);          // целая мелкая рамка лучше обрезанной крупной
    phone.style.transform = frameScale > .999 ? '' : 'scale(' + frameScale.toFixed(4) + ')';
  }
  ```
  `transform-origin: 50% 50%`, рамка по центру флексом. Внутри ничего не меняется: рендерер
  получает те же `410×820`, а CSS-уменьшение только добавляет плотности пикселей.
  Что важно знать, чтобы не чинить несуществующее:
  - **ввод править не надо**, если луч считается от `canvas.getBoundingClientRect()` — этот
    прямоугольник уже визуальный, трансформ в нём учтён (проверено перетаскиванием на
    `scale .717`: прицел и посадка клетка в клетку);
  - **DOM-подписи поверх игры тоже не надо** — они дети рамки и живут в её нескейленных
    координатах, то есть `toScreen()` по `phone.clientWidth/Height` остаётся верным;
  - а вот **тесты, которые синтезируют pointer-события**, обязаны переводить координаты:
    `clientX = rect.left + x * frameScale`. Иначе на уменьшенной рамке drag просто не начнётся,
    и это выглядит как сломанная игра, хотя сломан тест.
  Замеры после правки: окно 1280×900 → `scale 1` (ничего не изменилось), 1280×620 →
  `scale .717`, видимая рамка `294×588` целиком в окне и полноразмерная внутренняя раскладка,
  900×500 → `scale .571`. Режим «на весь экран» и телефон (`< 768 px`) трансформа не получают.
- Игровое время, стоп-кадр, `timeScale` и очередь событий — с первого дня (§6).
- Фиксированные подшаги физики, ограничение на число шагов за кадр.
- Пулы для всех частиц, никакого `new` в кадре.
- Флаг `testing`: автопилот гоняет уровни на скорости ×4–6 без звука и тяжёлых эффектов, но с
  проверкой, что логика и картинка совпадают (`DC.check()`, `SD.test()` → `won / end / left: 0`).
- `.run(sec)` в отладочном объекте: вкладка превью в фоне не рисует кадры.
- Для строк, которые обновляются из кода, перезапускай CSS-анимацию через
  `el.classList.remove(c); void el.offsetWidth; el.classList.add(c)`.
- **Canvas 2D: отрицательный радиус роняет весь кадр.** `ctx.arc` с `r < 0` бросает
  `IndexSizeError` прямо посреди отрисовки, `restore()` не вызывается, и в следующих кадрах
  текут `globalAlpha`, `clip` и трансформация — на экране чёрные кляксы, белые кольца и
  «ленты». Симптом выглядит как порча буфера, а причина — одна арифметическая ошибка в
  анимации (у нас фаза демо уходила в минус). Лечить **в самой нижней точке**: зажимать
  аргумент там, где он превращается в радиус (`press = clamp(press, 0, 1)`), а не в каждом
  вызывающем. Если на канвасе появился необъяснимый мусор — первым делом ищи исключение
  внутри кадра, а не ошибку в рисовании.
- **Правило, которое превращает след в препятствие, ломает жадную генерацию.** Пока комбайн
  мог ехать по своему следу, маршрут собирался жадным проходом; как только след стал
  блокирующим, жадный поиск перестал покрывать поле вовсе (7×7: 0 из 20 000 попыток).
  Замена — перебор с возвратом по всему полю, и к нему два обязательных довеска: требовать
  **минимум** препятствий (у нас 45% от потолка, иначе поле проходится спиралью вообще без
  камней) и ограничивать перебор числом узлов. Проверка «решение ещё существует» при этом
  обязана быть **трёхзначной** (есть / доказано нет / не успели): двузначная при нехватке
  узлов объявляет тупиком живую позицию и отбирает у игрока ход ни за что.
- **Бюджет генерации меряй на всех уровнях сразу.** Новое правило («не бывает областей в одну
  клетку») подняло худший уровень до секунды; лечится не ослаблением правила, а повторами
  дешёвой части (до 14 попыток разрезки на один найденный маршрут) — худшее время вернулось
  к 270 мс. В автотесте держи колонку «мс» по каждому уровню, иначе просадку замечает уже
  пользователь.
- **Правь большой HTML только по якорям.** Удаление по номерам строк и многострочные
  `perl -0pi` на файле в 350 КБ пару раз обрезали начало файла и разорвали чужой комментарий
  (вставка функции попала внутрь `/* ... */`, и браузер молча терял весь скрипт). Перед
  правкой — копия `.bak`, после правки — перезагрузка превью и взгляд в консоль.
- **Куча шаров/кругов: ползучесть лечится сном, а материал должен быть скользким** (Junk Drop).
  PBD-решатель гасит скорость между шагами (у нас было `× .98` на подшаг — это `× .09` за секунду!),
  и шары бесконечно ползают микроскоростями, ища место: «очень долго шары скользят, пока займут
  позицию». Первый порыв — добавить касательное трение — **неверен**: на `.2–.7` куча встаёт
  арками, между шарами дыры, а шары залипают на склоне («залипают сверху и не соскальзывают»);
  на слабом трении, но с сильным затуханием получается кисель («очень вязкие»). Правильно —
  сделать материал **льдом** и остановку отдать сну:
  1. *Лёд*: трение `.012`, сохранение скорости `.999` на подшаг, горизонтальное затухание `.06`,
     затухание вращения `.45`. Скользкая куча укладывается **быстрее** вязкой (1.2–2.7 с против
     2.8–6 с) и ложится плоско (3 ряда против 3.9 — трение строит башню).
  2. *Засыпание*: медленнее `R × .6` дольше 0.25 с → тело перестаёт считать гравитацию и скорость.
  3. *Спать можно только устойчивому*: опора под собой (`|dx| < .38 × (r1+r2)`), или развилка —
     контакт и слева, и справа (соседи вровень тоже считаются, стенки поля тоже), или пол.
     Лежащий на плече кучи неустойчив, не засыпает и скатывается сам.
  4. *Порог пробуждения мягче порога засыпания* (1.25 против 1.12 от `(r1+r2)²`), иначе шар на
     границе контакта мигает «уснул–проснулся» и не останавливается. Будить при толчке
     (`> R × .02`), при выносе соседа (радиус ~4R и вся колонка выше) и при потере опоры.
  Метрики из консоли: время до «все спят», «живые» кадры после остановки (должно быть 0),
  высота кучи в рядах (растёт башня = трение велико) и число уснувших без опоры (тоже 0).
  Осторожно: когда тела перестают ползать, проверка переполнения («лежит выше линии N секунд»)
  начинает срабатывать честно — куча больше не «сбрасывает» таймер микродвижениями. На льду это
  компенсируется само (куча плоская), на вязкой физике пришлось бы поднимать запас по высоте.

## 16. Чек-лист перед сдачей

- [ ] Ядро: объект следует за пальцем в реальном времени, ввод не теряется (буфер, удержание).
- [ ] У каждого события игрока есть пакет отклика: движение + частицы + звук + вибрация.
- [ ] Сила эффектов растёт по лестнице §4, у главного успеха есть стоп-кадр 40–50 мс.
- [ ] Игровые события звучат материалом (транзиент обязателен, у каждого материала свой
      звук); мелодия — на абстрактных успехах и экране результата.
- [ ] Ноты успеха не выше 1400 Гц: мажорная пентатоника от C5 с фолдом на октаву вниз (§8).
- [ ] Всё появляется пружинкой, исчезает облачком, перемещается по дуге; группы — каскадом.
- [ ] Цель подсвечивается заранее, ошибка видна до того, как её сделали.
- [ ] Звук сухой и короткий: только sine, атака 4–6 мс, реверберация 0.45 с wet 0.12,
      у каждого звука есть шумовой транзиент; в консоли нет предупреждений о частоте.
- [ ] Победа — праздник на 1–1.5 с, переход между уровнями анимирован.
- [ ] Ошибка мягкая, проигрыш с досмотром и «Ещё раз» на той же раскладке.
- [ ] Во всплывающих надписях только цифры.
- [ ] Обучение приходит в момент, когда правило понадобилось, и не зовёт к недоступному
      действию; карточка без заголовков, жест показывает рука (§11).
- [ ] Трата ресурса видна в месте действия и летит в счётчик; платим за откат, а не за игру.
- [ ] Проверено в превью 375×812, консоль чистая, автотест проходит.
- [ ] Проверено на низком окне десктопа (например 1280×620): рамка уменьшается целиком и

```js
var now = 0, freeze = 0, timeScale = 1, events = [], shake = 0;
function hitstop(sec){ freeze = Math.max(freeze, sec); }
function after(sec, fn){ events.push({ t: now + sec, fn: fn }); }
function tick(rdt){                           // rdt — реальный dt, обрезанный до 0.05
  var dt;
  if (freeze > 0){ freeze -= rdt; dt = 0; } else dt = rdt * timeScale;
  now += dt;
  var due = events.filter(function(e){ return e.t <= now; });
  if (due.length){
    events = events.filter(function(e){ return e.t > now; });
    due.sort(function(a, b){ return a.t - b.t; }).forEach(function(e){ e.fn(); });
  }
  update(dt);
  placeCamera();
  if (shake > .001){
    camera.position.x += (Math.random() - .5) * shake;
    camera.position.y += (Math.random() - .5) * shake;
    camera.position.z += (Math.random() - .5) * shake * .6;
    shake *= Math.exp(-rdt * 11);
  }
}
```

```js
function approach(x, t, k, dt){ return x + (t - x) * (1 - Math.exp(-k * dt)); }
function easeOutCubic(p){ return 1 - Math.pow(1 - p, 3); }
function easeInOutQuad(p){ return p < .5 ? 2 * p * p : 1 - Math.pow(-2 * p + 2, 2) / 2; }
function easeOutBack(p, s){ s = s == null ? 1.70158 : s; var c = s + 1; return 1 + c * Math.pow(p - 1, 3) + s * Math.pow(p - 1, 2); }
function elastic(p){ if (p <= 0) return 0; if (p >= 1) return 1; return Math.pow(2, -10 * p) * Math.sin((p * 10 - .75) * 2 * Math.PI / 3) + 1; }

function spring(o, k, c, dt){ o.v += (-k * (o.x - o.rest) - c * o.v) * dt; o.x += o.v * dt; }
var sq = { x: 1, rest: 1, v: 0 };             // посадка: sq.v = -2.4; подбор: -3.4; удар о пол: -4.2

function squashPop(model, t0, A){             // «чпок» без состояния
  var q = now - t0;
  if (q > .6){ model.scale.setScalar(1); return; }
```

```js
function tileKick(c, r, strength, radius){
  radius = radius || 3.2;
  tiles.forEach(function(t){
    var d = Math.hypot(t.c - c, t.r - r);
    if (d > radius) return;
    var imp = -strength * (1 - d / radius);
    if (!t.kickT || imp < t.kickImp){ t.kickT = .001 + d * .05; t.kickImp = imp; }
  });
}
function updateTiles(dt){
  tiles.forEach(function(t){
    if (t.kickT){ t.kickT -= dt; if (t.kickT <= 0){ t.kickT = 0; t.v += t.kickImp; } }
    t.v += (-320 * t.y - 16 * t.v) * dt; t.y += t.v * dt;
    t.mesh.position.y = t.baseY + t.y;
  });
}
```

```js
function flyStep(it){                          // it.fl = {t0, dur: .46, from, s0, ry}
  var p = Math.min(1, (now - it.fl.t0) / it.fl.dur), e = easeInOutQuad(p);
  var to = targetOf(it), from = it.fl.from, dist = from.distanceTo(to);
  var cx = (from.x + to.x) / 2, cy = (from.y + to.y) / 2 + .8 + dist * .2, cz = (from.z + to.z) / 2 + 1.6;
  var a = (1 - e) * (1 - e), b = 2 * (1 - e) * e, c = e * e;
  it.g.position.set(from.x * a + cx * b + to.x * c, from.y * a + cy * b + to.y * c, from.z * a + cz * b + to.z * c);
  var s = it.fl.s0 + (targetScale(it) - it.fl.s0) * e;
  it.g.scale.setScalar(s * (1 + .28 * Math.sin(Math.PI * e)));
  it.g.rotation.set(.3 * Math.sin(Math.PI * e), it.fl.ry * (1 - e) + Math.PI * 2 * e, 0);
  if (p >= 1) land(it);                        // приземлился: сплющивание + кольцо + искры + нота + buzz(5)
}
```

### Звук (сухой набор, §8)
```js
var AC = null, master = null, revIn = null, noiseBuf = null, muted = false;
var F_MAX = 1400;                                // потолок мелодии; выше — писк
function fclamp(f){ while (f > F_MAX) f /= 2; return f; }   // не обрезаем, а сворачиваем на октаву вниз
function rnd(a, b){ return a + Math.random() * (b - a); }
function jit(){ return 1 + rnd(-.05, .05); }     // живая вариация высоты, а не лестница нот
var sndLast = {};
function gate(k, ms){                            // не чаще раза в ms на тип звука
  var t = performance.now();
  if (sndLast[k] && t - sndLast[k] < (ms || 40)) return false;
  sndLast[k] = t; return true;
}
function audioInit(){
  if (AC){ if (AC.state === 'suspended') AC.resume(); return; }
  try { AC = new (window.AudioContext || window.webkitAudioContext)(); } catch(e){ return; }
  master = AC.createGain(); master.gain.value = muted ? 0 : .6;
  var hs = AC.createBiquadFilter(); hs.type = 'highshelf'; hs.frequency.value = 3200; hs.gain.value = -5;
  var lp = AC.createBiquadFilter(); lp.type = 'lowpass'; lp.frequency.value = 5200; lp.Q.value = .4;
  var comp = AC.createDynamicsCompressor();      // быстрый: подчёркивает транзиент
  comp.threshold.value = -16; comp.ratio.value = 3; comp.attack.value = .004; comp.release.value = .2;
  master.connect(hs); hs.connect(lp); lp.connect(comp); comp.connect(AC.destination);
  // совсем маленькая комната: только чтобы звук не был «в вате»
  var n = Math.floor(AC.sampleRate * .45), ib = AC.createBuffer(2, n, AC.sampleRate), ch, i, v;
  for (ch = 0; ch < 2; ch++){ var d = ib.getChannelData(ch);
    for (i = 0; i < n; i++) d[i] = (Math.random() * 2 - 1) * Math.pow(1 - i / n, 3.2); }
  var conv = AC.createConvolver(), rlp = AC.createBiquadFilter(), wet = AC.createGain();
  conv.buffer = ib; rlp.type = 'lowpass'; rlp.frequency.value = 3000; wet.gain.value = .12;
  conv.connect(rlp); rlp.connect(wet); wet.connect(master); revIn = conv;
  // чуть «розовее» белого: воздух, а не шипение и не вата
  noiseBuf = AC.createBuffer(1, Math.floor(AC.sampleRate * 2), AC.sampleRate);
  var nd = noiseBuf.getChannelData(0); v = 0;
  for (i = 0; i < nd.length; i++){ v = (v + .08 * (Math.random() * 2 - 1)) / 1.08;
    nd[i] = Math.max(-1, Math.min(1, v * 3.2)); }
}
function tone(f, dur, vol, delay, f1, atk, rev){
  if (!AC || muted || testing) return;
  if (f > 2200) console.warn('SND: слишком высокая частота', f);    // ловушка на этапе разработки
  var t = AC.currentTime + (delay || 0), o = AC.createOscillator(), g = AC.createGain();
  o.type = 'sine'; o.frequency.setValueAtTime(f, t);
  if (f1) o.frequency.exponentialRampToValueAtTime(f1, t + dur);    // только вниз
  g.gain.setValueAtTime(.0001, t);
  g.gain.exponentialRampToValueAtTime(vol, t + (atk || .006));      // атака 4–6 мс
  g.gain.exponentialRampToValueAtTime(.0001, t + dur);
  o.connect(g); g.connect(master);
  if (rev){ var s = AC.createGain(); s.gain.value = rev; g.connect(s); s.connect(revIn); }
  o.start(t); o.stop(t + dur + .05);
}
function noise(dur, vol, f0, q, delay, f1){      // lowpass с развёрткой вниз: тело и воздух
  if (!AC || muted || testing) return;
  var t = AC.currentTime + (delay || 0), s = AC.createBufferSource(), fl = AC.createBiquadFilter(), g = AC.createGain();
  s.buffer = noiseBuf; s.playbackRate.value = .9 + Math.random() * .2;
  fl.type = 'lowpass'; fl.frequency.setValueAtTime(f0, t); fl.Q.value = q || .7;
  if (f1) fl.frequency.exponentialRampToValueAtTime(f1, t + dur);
  g.gain.setValueAtTime(.0001, t);
  g.gain.exponentialRampToValueAtTime(vol, t + .006);
  g.gain.exponentialRampToValueAtTime(.0001, t + dur);
  s.connect(fl); fl.connect(g); g.connect(master); s.start(t, Math.random() * .5); s.stop(t + dur + .05);
}
function nbp(dur, vol, f0, q, delay, f1){        // bandpass: щёлк, чвак, шкварчание, «вжух»
  if (!AC || muted || testing) return;
  var t = AC.currentTime + (delay || 0), s = AC.createBufferSource(), fl = AC.createBiquadFilter(), g = AC.createGain();
  s.buffer = noiseBuf; s.playbackRate.value = .9 + Math.random() * .2;
  fl.type = 'bandpass'; fl.frequency.setValueAtTime(f0, t); fl.Q.value = q || 2;
  if (f1) fl.frequency.exponentialRampToValueAtTime(f1, t + dur);
  g.gain.setValueAtTime(.0001, t);
  g.gain.exponentialRampToValueAtTime(vol, t + .004);
  g.gain.exponentialRampToValueAtTime(.0001, t + dur);
  s.connect(fl); fl.connect(g); g.connect(master); s.start(t, Math.random() * .5); s.stop(t + dur + .05);
}
function clicks(n, vol, f0, f1, gap){            // рой щелчков: треск, хруст, стекло
  for (var i = 0; i < n; i++)
    nbp(.01 + Math.random() * .012, vol * rnd(.55, 1), rnd(f0, f1), 3.5, i * gap * rnd(.6, 1.4));
}
function blip(f, vol, delay, dur){               // тап по объекту
  f = fclamp(f); dur = dur || .09;
  noise(.02, vol * .5, 2600, .7, delay, 900);                       // щелчок-транзиент
  tone(f, dur, vol, delay, f * .45, .004);
  tone(f / 2, dur * 1.3, vol * .3, delay, 0, .006);
}
function tock(f, vol, delay){                    // стук дерева/пластика
  f = fclamp(f || 420);
  noise(.025, vol * .55, 1800, .7, delay, 600);
  tone(f, .1, vol, delay, f * .72, .004);
  tone(f * 1.52, .055, vol * .3, delay, 0, .004);
}
function ding(f, vol, delay, dur){               // маримба: единственный звук с хвостом
  f = fclamp(f); dur = dur || .34;
  tone(f, dur, vol, delay, 0, .005, .3);
  if (f * 2 <= 2200) tone(f * 2, dur * .3, vol * .22, delay, 0, .004, .2);
  tone(f / 2, dur * .7, vol * .25, delay, 0, .008);
}
function pop(vol, f0){                           // хлопок губами / лопнувший пузырь
  vol = vol || .12; f0 = f0 || 820;
  noise(.03, vol * .6, 3000, .8, 0, 700);
  tone(f0, .07, vol, 0, f0 * .28, .004);
  tone(f0 / 2, .1, vol * .4, 0, 0, .006);
  noise(.1, vol * .18, 700, .5, .04, 260);                          // выдох
}
function tap(vol){ vol = vol || .07;             // мягкое нажатие вместо щелчка
  noise(.03, vol * .8, 1500, .6, 0, 500); tone(300, .07, vol * .8, 0, 150, .004); }
function swish(vol, delay){ noise(.16, vol || .035, 1800, .6, delay || 0, 420); }
function rustle(dur, vol){ noise(dur || .18, vol || .03, 1400, .5, 0, 420); }
function thud(vol, f0, f1, dur){ noise(.04, .09 * vol, 1200, .6, 0, 300);
  tone(f0 || 180, dur || .12, .18 * vol, 0, f1 || 70, .005); }
// Материалы (Smash Fest): слои из таблицы §8. Каждый звучит по-своему, нот внутри нет.
var MAT = {
  crack:  function(){ if (!gate('crack')) return; clicks(4, .15, 2600, 4800, .013); noise(.03, .07, 1500, .8, 0, 700); },
  egg:    function(){ clicks(5, .15, 2400, 4600, .011); noise(.18, .24, 1100, 1.2, .02, 240);
                      nbp(.08, .09, 850, 1.5, .03); tone(105, .1, .1, .02, 55, .005); },
  tomato: function(){ noise(.24, .3, 1500, 1, 0, 200); nbp(.1, .13, 620, 1.4, .01); tone(82, .14, .2, 0, 44, .005); },
  crunch: function(){ clicks(7, .12, 1400, 3400, .012); noise(.09, .15, 850, .8, 0, 400); },
  glass:  function(){ clicks(9, .09, 2800, 5600, .009); noise(.22, .14, 500, 1, .03, 150); },
  chunk:  function(){ noise(.1, .18, 480, .7, 0, 240); tone(105 * jit(), .18, .26, 0, 48, .005); },
  soft:   function(){ if (!gate('soft', 80)) return; noise(.12, .14, 650, 1, 0, 230); tone(115, .12, .12, 0, 78, .006); },
  squirt: function(){ nbp(.2, .18, 450, 2, 0, 1300); noise(.12, .1, 380, .8, .05, 200); },
  sizzle: function(n){ nbp(.025 + Math.random() * .05, (.012 + Math.random() * .025) * Math.min(1.6, .6 + n * .1),
                          2600 + Math.random() * 2400, 1.6); }
};
// сила и комбо = плотность: тот же звук плюс слои, а не выше
function matHit(mat, combo){
  mat();
  if (combo >= 2) after(.02, MAT.chunk);
  if (combo >= 4) thud(1, 150, 60);
}
var PENTA = [0, 2, 4, 7, 9], BASE = 523.25;      // мажорная пентатоника от C5
function note(step, combo){
  var s = step + Math.min(combo || 0, 4);
  return fclamp(BASE * Math.pow(2, (PENTA[s % 5] + 12 * Math.floor(s / 5)) / 12));
}
var SND = {
  press: function(){ tap(.07); },
  land:  function(v){                            // стук о кучу, не чаще раза в 40 мс
    if (!gate('land', 40)) return;
    tock(360 + Math.floor(Math.random() * 60), .07 * Math.max(.12, Math.min(1, v)) + .02, 0); },
  burst: function(k){ pop(.12, 880 - (k % 4) * 60); },               // лопнуло
  slot:  function(i){ pop(.085, 620 - i * 30); rustle(.14, .025); }, // село на место
  fly:   function(){ swish(.03); },
  smash: function(combo){ matHit(MAT.egg, combo); },                 // разбил материал
  good:  function(step, combo){ ding(note(step, combo), .1); },      // абстрактный успех: можно нотой
  chord: function(k){                            // короткое арпеджио вверх
    var root = note(Math.min(k, 4), 0);
    [0, 4, 7].forEach(function(s, i){ ding(root * Math.pow(2, s / 12), .085, i * .07, .3); }); },
  stars: function(i){ ding(note([3, 4, 5][i], 0), .09, i * .14); },  // экран результата
  win:   function(){
    [0, 2, 4, 5].forEach(function(s, i){ ding(note(s, 0), .09, i * .11, .42); });
    ding(note(7, 0), .08, .46, .7); noise(.5, .025, 1600, .5, .46, 500); },
  lose:  function(){ [0, -3, -7].forEach(function(s, i){ ding(392 * Math.pow(2, s / 12), .08, i * .15, .4); });
    tone(131, .4, .05, .3, 98, .01); },
  hurt:  function(){ noise(.16, .07, 700, .6, 0, 220); tone(220, .2, .11, 0, 90, .006);
    tone(165, .24, .06, .07, 110, .008); }
};
```
